# MCP Tool Display Names (LLM-generated) + Chore LLM Setting

**Date:** 2026-07-02
**Status:** Draft

## Goal

Give each registered MCP tool a human-friendly **display name** generated by an LLM, shown to users instead of the raw tool identifier. Display names follow the fixed structure `{McpServerName} {Verb} {Noun}` (server name and verb are single words; the noun may be multiple words when needed).

To power this (and future background tasks such as director routing), introduce a reusable **Chore LLM** setting: a user-selected `(provider, model)` pair referencing an already-registered LLM.

## Locked decisions

1. **Chore LLM is a `(provider, model)` reference** into already-registered providers. It stores **no secret** of its own — the key is resolved at call time via the existing `KeyManager::get_api_key(provider_name)`.
2. **New Settings view** (`/settings`) with a sidebar entry holds the Chore LLM selector (no settings page existed before).
3. **LLM call lives in Rust**, using `async_openai` (non-streaming `create`), consistent with `src-tauri/src/api.rs`.
4. **Cache in `localStorage`**, keyed by a hash of the tool `description`: `{ [hash(description)]: displayName }`.
5. **Eager generation**: after `refreshAllTools`, uncached tools are sent to the backend in a **single batched** request (one LLM round-trip regardless of count).
6. **Graceful fallback**: if no Chore LLM is configured or the call fails, tools render with their raw `name`. Display-name generation never blocks tool loading.

## Architecture

### Backend — config

`src-tauri/src/configs/mod.rs`:
- Add to the `Config` struct:
  ```rust
  #[serde(default, skip_serializing_if = "Option::is_none")]
  chore_llm: Option<ChoreLlmRef>,
  ```
  where
  ```rust
  #[derive(Debug, Clone, Serialize, Deserialize)]
  pub struct ChoreLlmRef {
      pub provider: String,
      pub model: String,
  }
  ```
- `ConfigManager`: `get_chore_llm() -> Option<ChoreLlmRef>` and `set_chore_llm(Option<ChoreLlmRef>) -> Result<(), ConfigError>` (follows the `default_responder_id` get/set pattern + `save()`).

### Backend — chore completion helper (internal, reusable)

New module `src-tauri/src/chore.rs`:
- Private async fn:
  ```rust
  async fn chore_complete(
      app_handle: &AppHandle<impl Runtime>,
      system: &str,
      user: &str,
  ) -> Result<String, String>
  ```
- Resolves `chore_llm` from `AppData.config_manager`; returns `Err("Chore LLM not configured")` if unset.
- Looks up the provider via `config_manager.get_provider(name)`; resolves key via `KeyManager::new("wisp").get_api_key(&provider.name)` (same as `api.rs:109-112`).
- Builds a non-streaming `async_openai` request (low `max_tokens`, `temperature: 0`) and returns the assistant text.
- This private helper is the single reuse point for future backend chores (e.g. director routing).

### Backend — display-name command

`src-tauri/src/chore.rs`:
```rust
#[tauri::command]
pub async fn mcp_generate_tool_display_names(
    app_handle: AppHandle,
    tools: Vec<ToolDisplayNameInput>,
) -> Result<HashMap<String, String>, String>
```
- `ToolDisplayNameInput { server_name: String, tool_name: String, description: Option<String> }`.
- Returns `{ tool_name -> display_name }`.
- Builds **one** batched prompt: a JSON array of `{server, name, description}`, instructing the model to return a JSON array of `{name, display_name}` where each `display_name` is `{ServerName} {Verb} {Noun}` (title-cased; noun may be multiple words; server name = the given `server_name`).
- Parses the JSON response defensively (falls back to raw tool name for any entry it cannot parse, never aborts the whole batch).
- Empty `tools` → returns empty map without calling the LLM.
- Registered in `lib.rs` `invoke_handler`.

`src/composables/useChoreLlm.ts`: thin wrapper exposing `choreLlm` ref + `save()` / `clear()`, loading on creation.

### Frontend — display-name enrichment + cache

Logic lives in `src/stores/mcp.ts` (or a small `useToolDisplayName` composable called from the store):
- Cache helpers over `localStorage["mcp:tool_display_names"]` (read/parse/write JSON object).
- `hashDescription(desc)`: `crypto.subtle.digest("SHA-256", ...)` → hex.
- New store action `enrichDisplayNames()`, invoked at the end of `refreshAllTools()` (after `tools.value` is populated):
  1. Attach cached `displayName` from localStorage for each tool (by description hash).
  2. Collect tools still missing a `displayName`.
  3. If none missing → done.
  4. Call `mcpGenerateToolDisplayNames([...])` once (batched). On success: write each result to the cache and attach to the corresponding tool. On error: log and leave tools without a display name (fallback).

### Frontend — UI

`src/components/McpServerDetails.vue`: tools `n-data-table` "Name" column renders `displayName ?? name` (display the friendly name; keep the raw `name` available, e.g. as a `title` tooltip).

## Data flow

```
[backend auto-connect] -> mcp_status_updated(connected)
   -> refreshAllStatuses + refreshAllTools
       -> registry_refresh/list_tools populate mcpStore.tools
       -> enrichDisplayNames:
            attach from localStorage cache (by hash(description))
            batch mcpGenerateToolDisplayNames(uncached)  -- Rust ->
                chore_complete (async_openai non-stream) -> parse JSON
            write cache + attach displayName
       -> UI re-renders McpServerDetails table with friendly names
```

Configuration flow:
```
SettingsView -> mcpSetChoreLlm({provider, model}) -> ConfigManager.save() -> configs.toml
```

## Error handling / fallbacks

- Chore LLM not configured → `enrichDisplayNames` catches the error, logs, tools fall back to `name`.
- LLM returns malformed JSON → per-entry defensive parsing; unparseable entries fall back to `name`; the whole batch never throws.
- Provider/model referenced by `chore_llm` later deleted → `get_provider` returns `None` → error surfaces in Settings UI (selected value cleared / marked invalid).
- No network / timeout → error logged; cached names still used where available.

## Out of scope

- Migrating director routing onto the chore LLM (future; the private `chore_complete` helper is the intended reuse point).
- Editing/regenerating individual display names manually.
- Persisting display names in the backend registry (cache is intentionally frontend localStorage keyed by description hash).
- Streaming the chore completion (non-streaming is sufficient for short batched responses).
